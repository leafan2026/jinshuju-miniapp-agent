# 阶段二①:前端交互 demo

目标:在写小程序代码前,用一个**单文件 HTML demo** 快速把界面与交互跑给客户看,确认无误再进入正式开发。

## 步骤

1. **问清业务场景。** 这个小程序给谁用、核心要展示 / 收集什么数据、主要页面与操作流程。信息不足就继续问,别急着画。
2. **产出 HTML demo。**
   - 单个自包含 HTML 文件(内联 CSS/JS),移动端优先(按微信小程序常见尺寸,如宽 375px)。
   - 用假数据模拟从金数据 tables 拉到的列表 / 详情,体现真实字段与交互(列表、详情、筛选、提交等)。
   - 样式贴近微信小程序观感(顶部导航、卡片、底部 tabbar 等按需)。
3. **交给客户确认。** 说明这是交互草样,请客户就页面结构、字段展示、操作流程给反馈。
4. **按反馈迭代**,直到客户确认。确认后记录最终页面与字段清单,供 `jinshuju-schema` 对齐数据结构、供 `deploy` 落地成小程序页面。

## 注意
- demo 只为确认交互,不接真实金数据、不放真实凭证。
- 把 demo 里出现的字段列成清单,阶段二②要据此和金数据 tables 做映射。
