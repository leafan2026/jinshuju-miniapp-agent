# 阶段二②:金数据表结构与字段映射

目标:确定小程序的数据存到金数据的哪些 tables、每个前端字段对应金数据哪个字段(及类型),必要时用金数据 MCP 建表 / 改表。

## 步骤

1. **梳理数据实体。** 根据确认后的前端 demo,列出要持久化的实体(如「商品」「订单」「预约」)。每个实体对应金数据的一张 form / table。
2. **和客户确认 tables。**
   - 先用 `connection_search` 搜索 `jinshuju` 当前提供的表单、数据表、字段或条目能力，并以返回的工具名、描述和 schema 为准；MCP 服务端能力会变化，不能把示例工具名当作契约。
   - 客户已有金数据表单:调用当前发现的只读工具读取结构,和需求核对。
   - 需要新表或修改已有表单/数据表:先和客户确认表名、用途和影响范围，再用当前发现的 MCP 写工具执行。所有写入、未知或新出现的能力都会走人工确认。
3. **字段映射。** 用 `references/field-mapping-template.md` 的表格,把「前端字段 → 金数据字段 → 类型 → 是否必填 → 备注」逐行填清。字段类型参照 `references/jinshuju-field-types.md`。
4. **确认后再动结构。** 任何 create / edit / delete 表结构或字段的操作,先把「要改什么」讲清楚,经客户确认(审批)后执行。
5. **规划增删改查。** 明确小程序运行时对每张表的读写(通常云函数只读 GET 列表 / 详情;写入按需),记录查询条件、分页、排序。

## 交接
产出「tables 清单 + 字段映射表」,供 `deploy` 阶段生成云函数取数逻辑与小程序页面绑定。
