# 阶段二②:金数据表结构与字段映射

目标：确定小程序的数据存到金数据的哪些 Tables、每个前端字段对应金数据哪个字段（及类型），必要时使用当前会话可用的金数据 MCP 建表或改表。

## 步骤

1. **梳理数据实体。** 根据确认后的前端 demo，列出要持久化的实体（如「商品」「订单」「预约」）。每个实体对应金数据的一张 form / Table。
2. **和客户确认 tables。**
   - 先搜索当前会话中金数据 MCP 提供的表单、数据表、字段或条目能力，并以返回的工具名、描述和输入 schema 为准；服务端能力会变化，不能把示例工具名当作契约。
   - 客户已有金数据表单：调用当前发现的只读工具读取结构，再和需求核对。
   - 需要新表或修改已有表单/数据表：先展示表名、字段、用途和影响范围；用户确认后，调用当前发现的 MCP 写工具。完成后再调用只读工具核验。
   - MCP 在当前会话不可用时，说明此会话无法执行，不假装已连接或已创建；不要要求用户为了建表而启动某个 Agent 框架、配置模型提供商或安装与金数据无关的 CLI。
3. **字段映射。** 用 [field-mapping-template.md](field-mapping-template.md) 的表格，把「前端字段 → 金数据字段 → 类型 → 是否必填 → 备注」逐行填清。字段类型参照 [jinshuju-field-types.md](jinshuju-field-types.md)。
4. **确认后再动结构。** 任何 create / edit / delete 表结构或字段的操作，先把「要改什么」讲清楚，经客户确认后执行。
5. **规划增删改查。** 明确小程序运行时对每张表的读写（通常服务端只读 GET 列表 / 详情；写入按需），记录查询条件、分页、排序。

## 交接
产出「tables 清单 + 字段映射表」,供 `deploy` 阶段生成云函数取数逻辑与小程序页面绑定。
