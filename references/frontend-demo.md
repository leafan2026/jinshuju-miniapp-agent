# 阶段二①:前端交互 demo

目标：在写小程序代码前，用一个**单文件 HTML demo** 快速把界面与交互跑给客户看，确认无误再进入正式开发。

## 步骤

1. **问清业务场景。** 这个小程序给谁用、核心要展示 / 收集什么数据、主要页面与操作流程。信息不足就继续问,别急着画。
2. **选择设计方向。** 先阅读 [design-directions.md](design-directions.md)；如客户尚未确定风格，打开 [style-gallery.html](style-gallery.html)，从与业务场景匹配的方向中让客户挑选。参考只用于色彩、版式密度和组件语言，不能复制品牌 Logo、插画、文案或将来源品牌暗示为客户产品。
3. **产出 HTML demo。**
   - 单个自包含 HTML 文件(内联 CSS/JS),移动端优先(按微信小程序常见尺寸,如宽 375px)。
   - 用假数据模拟从金数据 tables 拉到的列表 / 详情,体现真实字段与交互(列表、详情、筛选、提交等)。
   - 样式贴近微信小程序观感(顶部导航、卡片、底部 tabbar 等按需)。
4. **交给客户确认。** 说明这是交互草样,请客户就页面结构、字段展示、操作流程和设计方向给反馈。
5. **按反馈迭代**，直到客户确认。确认后记录最终页面、字段清单和选定设计方向，供表结构映射与小程序实施对齐。

## 注意
- demo 只为确认交互,不接真实金数据、不放真实凭证。
- 把 demo 里出现的字段列成清单,阶段二②要据此和金数据 tables 做映射。
- 不得从参考站点复制商标、插画、截图、字体文件、业务文案或受保护素材；仅提炼通用的视觉原则。
