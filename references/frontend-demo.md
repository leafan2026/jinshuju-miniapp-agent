# 从设计参考到可交互样机

## 已有 HTML、截图或成品

先读用户给出的原文件、样式、脚本和资源，结合当前已确认的改进，按 [设计与交互规范](design-spec.md) 提取页面、组件、状态和动作。截图只能说明拍摄时的状态；不能凭截图猜手势、保存逻辑和字段类型。

不另选主题、不擅改布局或用四个通用列表替换真实交互。系统状态栏、模拟手机外壳和假微信胶囊仅是原型呈现辅助，不复制进业务 UI。原文件不可访问时明确未比对的部分，不编造“完全一致”。

## 没有原型

按场景提出一个有依据的主方向；必要时给少量备选。可读 [设计方向](design-directions.md)，无需强制打开浏览器或要求用户逐页选风格。

用移动端可交互 HTML 或用户指定工具表达关键路径；单文件 HTML 是便于分享的选择，不是所有项目的强制技术限制。数据尚未建表时使用明确标记的拟议字段和假数据。已有表时核实类型后模拟，不复制个人信息。

## 样机应证明什么

- 列表 → 详情 → 新增/编辑 → 保存或取消 → 返回，按业务选择必要流程。
- 搜索、筛选、选中、加载、无结果、失败和重试；展示数据不足时也能理解操作。
- 抽屉、堆叠、日历或手势若属于要求，就实现可操作的状态变化，不能用 toast 替代。
- 给出与页面匹配的字段清单，以及仍待确认的决策。样机保存只是内存行为时明确说明，不把它说成真实持久化。

只对关键设计选择和明显偏离参考的方案取得确认，不用逐个像素询问拖慢实施。确认后将版本/截图基线、交互规则写入应用的设计规格，作为移植验收依据。

## 素材

使用用户允许用于该用途的素材或可合法分发的资源；样机使用许可不自动包含公开分享许可。不得复制参考品牌的 Logo、文案、字体文件和图片。假数据与素材都不得带入真实凭证。
