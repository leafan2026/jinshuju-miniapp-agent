# 需求与接入准备

先理解业务，再按阶段准备权限。不要把收集所有凭证当成画原型或写模拟代码的门槛；只询问会改变下一步决策的缺失项，已给出的信息直接沿用。

## 需求与范围

- 谁使用、谁维护？公开查询、单人私用、团队共享、多用户隔离分别处理。定义每类角色对记录的读/写/删除范围。
- 用户要完成什么？描述主路径、返回路径、失败与撤销，而不只是列页面名称。
- 已有 HTML、截图、成品、数据表或代码吗？核实版本和路径；区分已确认效果与历史参考。
- 有哪些实体、关系、业务状态、日期规则、图片与个人资料？哪些统计派生、哪些字段持久化？
- 确认应用输出仓库与 Skill 仓库的区别，以及浏览器、MCP、CLI、推送、部署的当前限制。

新应用使用提议的模型做假数据，明确“未绑定真实字段”；旧应用先读当前表与代码，保留用户已有数据与交互。

## 什么时候需要什么

| 阶段 | 需要准备 | 不必提前提供 |
| --- | --- | --- |
| 需求、设计、模拟实现 | 场景、原型/素材及使用权、目标工作区 | Access Token、上传私钥、线上服务 |
| Agent 建表/核对数据 | 当前会话的金数据 MCP 连接和授权、操作目标与范围 | 启动其他 Agent 框架或配置模型商 |
| 开发者工具项目/预览 | 用户自己的 AppID、开发权限、项目路径 | 向 Agent 提交上传私钥 |
| 后端真实联调 | 云托管环境/服务、金数据 Access Token 的受控配置、所选认证方案 | 其他案例的生产凭证与资源 |
| 后端发布 | 目标仓库/分支/目录/端口、实际触发方式、发布权限 | 一个没有任何代码读取的“必填部署模式”环境变量 |
| CI/CLI 上传（可选） | AppID、受控上传私钥、上传运行环境授权及适用白名单 | 明文私钥进聊天 |
| 开发者工具手动上传 | 已登录且有权限的开发者工具、版本说明 | 向 Agent 提供 CI 私钥 |

金数据 Access Token 只保存到受控配置，程序负责添加 Bearer 前缀。Agent 的 MCP 授权成功不证明云托管已有运行凭证。

## 网络与访问

按当前金数据接入规则核对权限和适用的出口 IP 白名单。以实际云托管网络和出口为准，不以开发者电脑 IP 代替；若需要固定出口，确认平台方案及成本后配置，不擅自采购。按图片与请求实际使用方式核对微信侧网络配置。

## 阶段完成条件

需求阶段有角色、流程、实体和范围即可进入设计。真实联调前才要求目标资源和所需秘密就绪。发布前另行核实触发方式与授权；缺项只阻塞相关阶段，不假装线上已完成，也不阻塞无关的本地工作。
