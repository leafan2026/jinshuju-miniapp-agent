# 交付不变量与常见故障

这些规则来自实际案例，但不要求所有项目采用同样的业务、身份或组件。改发布与数据流程时按需核对。

| 症状/风险 | 先检查的证据 | 不应采用的替代动作 |
| --- | --- | --- |
| 云托管项目出现 callFunction 找不到资源 | 实际测试前端包的调用、环境与目标服务 | 创建云函数来掩盖架构错误 |
| 报缺少运行秘密 | 请求对应的版本、该版本配置存在性、实际流量、代码读取的变量名 | 输出秘密值、直接断言旧实例、反复推 main |
| 金数据请求失败 | 区分应用与上游状态码，核实凭证配置、目标权限及适用网络规则 | 把所有 401/403 都说成同一个问题 |
| 数据全为零 | 请求是否成功、响应解析、字段/选项映射、筛选、日期、完整分页 | 把错误当空表，重新灌入假数据 |
| 保存后变回旧内容 | 写入读回、局部更新、缓存失效、晚到旧请求 | 整条旧记录重发，重复创建 |
| MCP 报假成功 | 传输内容类型、JSON-RPC error、工具 isError；SSE 按事件解析 | 将多个事件拼为一个 JSON 或只看 HTTP 200 |
| 图片不显示 | 附件结构、有效期、缓存文件、实际资源权限与路径 | 认为业务登录成功就一定有图片权限 |
| 重复部署/版本不明 | 本次触发、监听分支、构建运行与版本关联、流量 | 叠加触发器、按时间猜、再部署验证 |
| UI 与原型差异 | 同数据/时间/视口/状态，原生按钮、导航与安全区、样式隔离 | 用截图物理像素硬调一台设备或把单测当视觉验收 |
| 误改仓库 | remote、路径、本次目标是 Skill 还是业务应用 | 在演示应用中持续堆通用 Skill |

## 交验而不是笼统说“完成”

分别记录：本地实现、静态与行为测试、开发者工具编译、界面/手势验收、真实数据联调、Git 同步、云托管运行版本、小程序预览/上传/审核/发布。

用户禁止浏览器、要求仅 MCP 或要求先验收再推送时，遵守对应约束。缺少某项工具只标注相应证据缺失，不伪造成功，也不通过另一渠道绕过限制。保存、推送、部署各自限定在授权的目标与范围内。
