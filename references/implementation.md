# 实现与联调约定

先在用户指定的应用仓库核对现有结构。新项目可将小程序、云托管服务、测试分别组织为 `miniprogram/`、`server/`、`tests/`；已有项目沿用当前结构和构建上下文，不为迁移文档移动部署目录。

## 接口与身份

小程序统一请求模块封装 `wx.cloud.callContainer`，指定配置中的环境、服务与业务路径，处理加载、错误、会话失效。服务端先认证/授权，再校验请求并调用金数据；不可让客户端任选表或上游 URL。

业务路由对页面暴露稳定业务字段，通过服务端适配层映射真实字段和选项。字段 key 并非秘密，但不应让业务页面依赖易变的上游结构。维护必要的接口版本兼容，校验允许更新的字段、记录标识、枚举、长度、日期范围。

新项目必须明确访问模型：共享口令只适合共享同一数据空间的场景；需要用户隔离时，用服务端可验证的身份和记录归属做每次读写授权。不相信客户端自行填写的 AppID、OpenID、角色或 owner。列表、详情、附件、写入均考虑权限，不能只在前端隐藏入口。

## 持久化与一致性

- 以真实接口契约处理全部分页和排序；遇上游错误、重复游标或安全上限，报告失败/不完整，而非展示“全部数据”。
- 更新只写修改字段。涉及多表关系、重命名、删除时定义稳定关联和部分失败恢复；Tables 不应被假定具备应用需要的跨表事务。
- 有缓存就定义生命周期、请求去重、写入后失效和登录退出隔离。旧读请求晚到不能覆盖新写入；先从简单可验证策略实现，再按数据量优化。
- 创建结果不明时先查询核验，不盲目重试造成重复；需要幂等标识时设计并验证其作用范围，不凭一个前端按钮禁用宣称后端幂等。
- 统一业务时区、日期和日期时间语义；排序与超时使用真实时间，测试注入固定时钟。不同实体编号可能相同，组合列表使用含实体类型的 key。

## 附件

按已验证的上传契约保存持久化附件标识；临时本地路径、短期 URL、云文件 ID 和金数据附件 ID 不混用。大图不要作为 Base64 塞进普通 JSON 业务请求。

服务端代理远程图片时限制来源、重定向、MIME、大小和超时，防止任意下载。明确原图的业务存储位置与缩略图缓存；只改文字不重复上传旧图。处理临时资源清理，但保存结果不明时不能误删已使用的资源。

## 验证

先用模拟上游验证映射、权限拒绝、分页、部分更新、并发与失败；不要往真实案例表写测试垃圾。真实联调限定于用户授权的表与记录，读回核验保存结果，保留既有数据。

界面验证依照 [设计规范](design-spec.md)。服务端构建验证依照 [部署](deployment.md)。修一个局部问题无需复制整个工作台的组件、缓存层或认证方案。
